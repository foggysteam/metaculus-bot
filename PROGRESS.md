## How the bot works
- Fork of the official template (`main.py` kept as upstream). Our code: `forecaster.py`, `claude_code_llm.py`, `run_bot.py`.
- Models: Claude via the Claude Code CLI (`claude -p`) on Ahmad's Max subscription. Research: two independent Opus reports per question with WebSearch/WebFetch (dated facts with links, resolution source, base rates, market prices; for numeric and discrete questions also the same calendar window in earlier years and the weather outlook), sharing one fetch of AskNews, market prices and the baseline. Forecasts: 3 Opus runs per report, 6 in all (effort high), template aggregation (median binary, mean MC, median CDF numeric). Parser: Haiku. Never Fable (it can bill extra in headless mode).
- Every question writes `forecast_logs/<date>/<time>-<id>-<slug>.json` (question, research, each forecast with reasoning, final forecast, usage) and a row in `forecast_logs/index.csv`.
- GitHub Actions: `.github/workflows/forecast.yaml`, polls for `LOOP_MINUTES` (repo variable, 300) every `POLL_SECONDS` (600). Each run keeps one more queued behind it, which takes over as soon as it ends, however it ends. Cron and `.github/workflows/watchdog.yaml` (`watchdog.py`) only restart the chain if it breaks. To stop everything, disable Forecast and Watchdog. A queued run uses the workflow file from when it was queued but pulls the latest code at its start, so after changing forecast.yaml, dispatch a new run to replace the queued one. Test and rescue runs have their own queue.
- Watchdog: restarts the chain if nothing is running, alerts on an open question with no forecast 45 minutes after opening, gives it a run of its own (mode=rescue) at 75 minutes, and starts the health check if it is overdue.
- Rules we follow: no human changes or reruns of tournament forecasts. Testing only on bot-testing-area, main-site questions (dry run), or closed questions.
